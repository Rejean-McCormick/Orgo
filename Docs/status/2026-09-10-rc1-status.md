## Incident Playwright résolu

Une première campagne étendue avait présenté des échecs intermittents sur E03, E04, E05 et E06.

L'analyse a montré que la cause se trouvait dans le **harness Playwright de LevelUpDiag-Orgo**, plus précisément dans la synchronisation du helper `openWork()` avec la recherche débouncée de l'interface.

Le helper a été renforcé afin de synchroniser explicitement les transitions de recherche avant l'ouverture du détail.

Après cette correction du harness :

- E03 : PASS
- E04 : PASS
- E05 : PASS
- E06 : PASS
- suite complète : 22/22 PASS deux fois consécutivement

**Aucun patch applicatif Orgo n'a été requis pour cet incident.**

La correction appartient à `LevelUpDiag-Orgo`, dépôt de diagnostic séparé.

## Incident Prisma résolu pendant le gate RC

Le premier lancement du gate RC a échoué sur `db:generate` avec :

`EPERM: operation not permitted, unlink ... query_engine-windows.dll.node`

La DLL Prisma était verrouillée par des processus Node Orgo encore actifs.

Les processus concernés ont été arrêtés, le client Prisma généré a été supprimé puis régénéré. `npm run db:generate` a ensuite réussi normalement.

Cet incident était lié à l'environnement Windows et au verrouillage du moteur Prisma, pas au schéma, aux migrations ni à la base.
