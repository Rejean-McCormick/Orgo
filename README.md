# Orgo dependency security update

This is a source overlay for the Orgo repository at:

`C:\mycode\Orgo\Orgo`

It is not a complete repository and it does not modify LevelUpDiag-Orgo.
Create a commit or backup first, then merge the archive into the Orgo root.

## Files

- `package.json`: forces the patched Multer release used below NestJS.
- `apps/api/package.json`: upgrades NestJS, Express types, js-yaml and Nodemailer.
- `apps/api/src/orgo/platform/outbox/worker.service.ts`: adapts SMTP transport
  timeout configuration to Nodemailer 10.

`package-lock.json` is intentionally not included. It must be regenerated by npm
on the destination system so its resolved URLs and integrity hashes correspond
exactly to the packages fetched from the configured registry.

## Apply in PowerShell

After merging the three files:

```powershell
cd "C:\mycode\Orgo\Orgo"
npm install
```

Use `npm install` once, not `npm ci`: the lock file still describes the old
dependency graph. Review the resulting `package-lock.json` and commit it together
with these source changes. Subsequent clean installations should use `npm ci`.

Then open `C:\mycode\Orgo\LevelUpDiag-Orgo` and run, in order:

1. `quick`
2. `embedded`
3. `build`
4. `security`

Expected security result: zero moderate, high or critical vulnerabilities.
Treat the actual LevelUpDiag N13 report as authoritative. Do not use
`npm audit fix --force`.
